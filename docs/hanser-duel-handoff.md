## 3. 用户希望获得的体验

- 用户认为旧玩法不好玩，希望改变战斗核心，而不只是装饰旧系统。
- 喜欢《光与影：33号远征队》中己方进攻和敌方回合都有操作参与的感觉，尤其是读动作、卡时机的节奏感。
- 喜欢 P5 的战斗画面、菜单、动作与镜头配合，以及成功操作或优势选择得到奖励的体验。
- 想把精力主要放在程序设计、战斗手感上，减轻敌人与角色美术制作负担。
- 单角色战斗需要容错，不希望必须连续完美操作才能存活。
- 战前搭配有意义，但不要求每个技能都有专门设计的组合技或特殊连携。

这些是参考体验，不代表照搬任何原作的全部系统。后续涉及原作具体机制时核对官方或开发者资料，并区分作品与版本；不能把《只狼》《绝区零》《崩铁》的队伍、资源、格挡、行动机制直接混为本项目规则。

## 4. 已确认：角色、战前搭配与成长方向

### 4.1 单角色与初版人数

- 只有一个可操控的白色圆团毛怪主角，没有可操控队伍。
- 毛怪没有明显外露的人形手脚，具体形象继续参考旧设定。
- **首个参考版只做 1V1：一名玩家角色对一名敌人。** 群战留到以后。

### 4.2 武器 / 信物与技能

- 用户计划后续加入满穗、银狼、布洛妮娅等角色相关遭遇，战胜后获得相应能力来源。
- 新方向是通过 **武器 / 信物** 承载能力；不再沿用旧随机能力卡、抽弃牌与提前准备队列。
- 每个武器 / 信物有几个自己的能力，玩家在角色界面搭配。
- 普通技能允许跨不同武器 / 信物自由混搭。
- 初版提供 **4 个普通技能槽**，以后是否扩展再说。
- 不强制规定几个攻击技能、几个辅助技能；四个位置由玩家自由选择。
- **大招只装备 1 个**，独立于四个普通技能槽。
- 普通攻击、物品入口独立存在，不占这四个槽位。
- 战斗中的“技能”菜单展示本次装备的技能。

武器 / 信物本身能装备几件、全部解锁流程、技能候选池数量、关内何时允许换装，均未最终确定。不能把“4 个技能槽”写成“4 件信物”或“所有信物总共只有 4 个技能”。

上述客串角色尚未确定具体正式技能、剧情动机或战斗结果。尤其要区分《崩坏3》的布洛妮娅与《崩坏：星穹铁道》的布洛妮娅；本轮没有确定采用哪个具体形态，也不能把二者的配音与技能设定混用。首个试玩可以先使用中性测试能力，不必先完成客串角色资源。

### 4.3 用户所说的“技能联动”

用户已澄清：首先指普通效果的自然配合。例如一个技能提高敌人受到的伤害，另一个技能攻击它，就自然受益；无需限定某两件信物或专门触发组合技。

- 每个技能先有独立、清楚的用途。
- 增益、减益、攻击等常规效果可以自然配合。
- 搭配取舍来自效果、行动顺序和费用。
- **特殊连携留到以后具体技能设计时再讨论。**

之前提出的“统一标记引爆系统”“统一叠层体系”等只是建议，没有被用户选为当前必需系统。也不是永远禁止个别技能具有特殊互动。

## 5. 已确认：行动顺序与战斗菜单

- 取消提前备招、逐回合入队、整组释放准备队列的旧核心。
- 直接选择并执行当前可用招式。
- 使用 **基于速度的可见行动顺序条**；具体算法、初始顺序、同速处理尚未确定。
- 当前菜单为 **攻击 / 技能 / 物品 / 大招**。
- **主动“防御”菜单已取消。** 不再制作对应的持续减伤、冷却回合或结束条件。
- 闪避与格挡是敌方攻击过程中的即时应对，仍然保留，不能与被取消的“防御指令”混淆。
- 用户允许弱化或取消六边形格子，新方向不再以格子走位为核心。首版可采用固定战斗站位作为实现建议，但没有确定正式自由移动、距离、站位加成系统。

一次正常行动选择一个常规行动。技能费用足够不意味着可以在该行动里无限连续施放。具体技能未来如有例外，应单独设计，不能从旧免费卡牌规则推导。

## 6. 已确认：卡点是按技能配置的可选奖励

- **卡点是可选模块**，普通技能和大招都由各自设计决定是否使用。
- 治疗、护盾、增益等辅助技能完全可以不带卡点。
- 不带卡点的技能正常执行完整效果。
- 带卡点的技能即使一次都没按中，也会执行基础伤害和基础效果。
- 成功次数可以增加伤害、附加效果或其他明确配置的奖励。
- 普通技能卡点成功可以额外获得大招能量。
- 不能把“没按中”改成技能失败、取消施放、失去全部伤害或失去原本承诺的基础辅助效果。
- 辅助技能也可以获得基础回能，具体收益另行调整，避免由于没有卡点机会而天然吃亏。

实现结构建议：把技能的费用、目标、基础效果与可选输入窗口分开配置；输入模块返回判定结果，由技能决定如何奖励。逻辑可分离，但输入窗口仍需与该技能的动作和关键时刻同步。

尚未确定每次基础回能量、成功点收益、哪些大招带卡点，以及大招自身是否能给大招能量回充。不能自动把同一回能规则套给所有行动。

## 7. 已确认：闪避、格挡与敌人连击

### 7.1 闪避与精准格挡

| 项目 | 当前规则 |
| --- | --- |
| 闪避 | 成功就避开对应这一击的伤害 |
| 格挡 | 需要精准卡点；成功免伤，并恢复少量技能资源 |
| 红光攻击 | 对应这一击不能格挡，需要通过闪避应对 |
| 单次失误 | 不自动判定整组失败，不剥夺后续攻击的应对机会 |

用户早期提出过“格挡成功减伤 90%”，后来因为单角色生存压力，已改成 **成功免伤**。不要保留成功格挡后的 10% 扣血。

格挡比闪避更精确、闪避相对宽容是当前讨论的方向；毫秒窗口、按早按晚结果、按住与连按处理尚未最终确定。当前没有确认新增体力条、格挡次数上限或回合冷却；被删除的主动防御冷却不能移植到精准格挡上。

闪避 / 格挡是否有额外费用、反复输入锁定及防止乱按的处理，需要在试玩实现方案中明确。若采用免费反应和短输入限制作为初版处理，须标明为临时实现选择，不能声称已有完整定稿。

### 7.2 逐击应对

- 敌人的一次行动可以包含多击。
- **每一击独立判定闪避或格挡。** 一次成功不能自动避开整组连击。
- 前一击失误受伤后，下一击仍能正常闪避或格挡；不可因受击硬直自动锁死剩余操作。
- 同一组连击中可以逐击选择应对方式，红光限制作用于对应的那一击。
- 整组连击属于敌人的一次完整行动。

例：第一击闪避成功 → 第二击格挡失误、受到该击伤害 → 第三击仍可成功格挡、免伤并恢复少量技能资源。

以上后续操作机会以角色仍存活为前提，不是死亡后仍继续操作的规则。致死处理、同一时刻输入与伤害先后的边界，需要实现时明确并验证。

### 7.3 试玩敌人建议，尚非正式技能表

此前建议用一个敌人验证：普通单击、短连击、红光攻击。用户确认的是 **初版 1V1**，没有给正式敌人身份、三招的具体效果、AI 顺序、伤害或动画定稿。

可以沿用这三类招式作为首版测试范围，但须作为占位测试内容说明。是否提前展示连击次数、是否显示节奏轨道、提示持续多久，尚未确定；红光提示本身不能被误当成已经约定的统一按键时刻。

## 8. 已确认：技力、物品与大招

### 8.1 普通技能费用

- 使用一个共同的技能费用条，主要限制强力技能，避免一直释放强招。
- “技力”是方便讨论的暂用名称，不是已确定的世界观术语。
- 普通攻击承担稳定恢复技能资源的作用，不应要求卡点成功才有基本恢复。
- 精准格挡成功提供少量额外恢复。
- 辅助技能应通过实际效果体现价值，不必全部设计为回资源按钮。

技能资源上限、初始量、普攻收益、格挡收益、各技能费用及是否有其他回收来源尚未定稿。之前出现的“上限 6、初始 3、普攻 +2”等只是举例，不是获准的正式数值。

### 8.2 物品与回血

- 保留物品入口，其中可以提供回血手段。
- **使用回血物品占用本次正常行动。**
- 回血物品不消耗技能费用，也不要求卡点。
- 单角色需要稳定的基础生存手段，不应完全依赖抽牌或某一客串能力。

携带数量、回复量、是否允许满血使用、战间补充、是否消耗其他资源尚未确定。之前提到的“2 次 / 每次 40%”不是已确认数值。

需要避免回血后立即损失同等或更多生命，形成只能不断回血的循环；这属于试玩验证重点，不是已经确定的数值公式。

### 8.3 独立大招能量

- 大招使用独立于技能费用的能量条。
- 大招属于 **常规爆发**：普通战斗也应有机会体验，不仅为少数关键战斗保留。
- 每个大招有自己的效果和能量需求，不能因为当前只装备一个就把所有大招都设计成同一费用。
- 技能卡点成功提供额外大招能量；基础回能的分配仍需配置。
- 战前只装备一个大招，普通技能可以继续跨信物混搭。
- 能量满足条件后由玩家选择使用，不自动施放。

能量上限如何显示、是否允许溢出储存、释放后扣除需求还是清空、开战能量及战间继承尚未确定。费用越低的大招能越频繁获得插入行动，其强度不能只按伤害衡量。

### 8.4 大招插入行动

- 大招作为额外行动插入，不消耗原本排定的正常行动。
- 当前动作或敌人整组连击必须完整结束，之后才能插入。
- 不能在一组连击中途打断敌人、跳过剩余攻击或逃避当前判定。
- 这次额外行动用于释放选定大招，不是额外获得一次可自由普攻、用物品或放普通技能的正常回合。

示意：敌人行动 → 玩家大招 → 原本排定的玩家正常行动。若大招请求发生在敌人三连击中，须先完整处理三击及对应反应。

尚未确定：重复请求如何处理、能量何时扣除、目标提前死亡、玩家提前死亡、对未来状态持续时间的影响。实现者需要说明临时处理并测试，不能暗中改变正常行动顺序。

此前“大招是否打断主动防御”的讨论已因主动防御指令取消而失去适用对象，不需要实现相关状态。

## 9. 表现方向与美术边界

### 9.1 保留的方向

- 正式游戏仍计划采用 Unity / C# / 2.5D。
- 探索偏好 PokeMMO 合众地区那类俯视或斜视空间表现。
- 战斗喜欢 P5、33 的人物构图、技能菜单、动态镜头和命中反馈。
- 主角仍是毛怪，而不是替换为人形队伍。
- 用户更希望把精力用于编程和手感，希望减少美术工作量。

### 9.2 尚未确定的技术与美术路线

曾讨论过“3D 场景配 2D 角色”“简模 3D 战斗舞台”“少量重复使用的镜头”等方案，但没有最终锁定正式渲染管线、素材包、模型、骨骼或角色动画方案。

不能仅凭 PokeMMO 静态截图，断言它每一种地图物体、角色、战斗资源都采用某种具体实现。用户截图表达的是偏好，不是本项目必须完全复刻的技术规范。

首版 HTML 可以使用占位毛怪、简化敌人、斜视战场、位移 / 缩放 / 镜头变化和命中反馈检验节奏。它不能单凭效果相似就证明正式 Unity 3D 镜头和资产管线已经验证。

## 12. 新版建议验证清单

以下均为**待执行检查**，不能写成已通过：

- 四技能和一个大招的装配结果与战斗菜单一致；攻击、物品不挤占技能槽。
- 无卡点技能可直接执行；带卡点技能零成功仍保留基础效果；成功只增加已配置的奖励。
- 普攻稳定恢复技能资源；费用不足不能执行对应技能；费用不会因重复输入扣两次。
- 普通技能费用与大招能量独立；不同大招需求能正确配置和显示。
- 闪避成功免除当前这一击；精准格挡成功免伤并恢复约定资源；红光那一击不能格挡。
- 三连击分别判定；一次成功不覆盖余下连击；前一击失误后仍能操作下一击。
- 大招请求等待当前完整行动结束；不在连击中途插入；插入后不吞掉玩家原本正常行动。
- 回血物品占用正常行动，不收技能费用、不要求卡点；数量和回复遵循本次临时参数。
- 结束战斗后不再接受旧动画、旧判定窗口或重复按钮造成的额外伤害、回能、行动推进。
- 实际玩到胜利与失败，检查重新开始、浏览器控制台错误和基本窗口尺寸下的可操作性。
- 手动体验提示能否读懂、输入与命中是否同步、失误是否可恢复；规则测试不能替代这些手感验证。

需区分“逻辑测试通过”“浏览器实际操作过”“美术 / 镜头尚未充分验证”。不需要重新做旧原型的全部测试来证明新原型有效，也不应为纯样式修改添加没有意义的镜像测试。
