# 憨之轨迹 · 回响之间

独立的 **1V1 HTML 战斗参考版**。规则依据 [新版交接](../../docs/hanser-duel-handoff.md) 和 2026-10-14 本聊天批准的实施范围。角色背景仍以 [game-setting.md](../../docs/game-setting.md) 为准。正式游戏方向仍为 Unity / C# / 2.5D。

## 打开与操作

用桌面 Chrome 或 Edge 打开本目录的 **index.html**。代码、样式和 Canvas 占位图形全部内嵌，无需安装依赖、联网或构建。浏览器验证的实际运行方式见 [VERIFICATION.md](VERIFICATION.md)。

1. 战前选满四个不同的普通技能和一个大招。点击已选技能取消，再选择其他技能；三种信物的能力可自由混搭。也可用 Tab、Enter 完成装配。
2. 在毛怪身旁的悬浮菜单中选攻击、技能、物品或大招。选择具体招式后进入目标预览，确认才执行；返回不会消耗资源。选招阶段不催促。
3. 技能带卡点时，光圈向内环收缩，在亮起时点击“共鸣”或按空格。漏按或按早仍保留基础效果。
4. 敌人攻击每击独立点击闪避／格挡，或按 J／K。红光只能闪避；下一击可以重新选择。
5. 大招满能量后，选招阶段先预览再确认；动作期间点击右下大招入口或按 R 预约，完整动作结束后插入，保留原定正常行动。

| 操作 | 键盘 | 鼠标 |
| --- | --- | --- |
| 选择菜单项 | ↑ ↓ 或 W S；Enter 进入 | 点击角色旁指令 |
| 快速选择当前列表项 | 1 / 2 / 3 / 4 | 点击对应项 |
| 确认目标并施放 | Enter | 点击目标框或“确认施放” |
| 取消目标 / 返回上层 | Esc | 返回 |
| 大招预览 / 动作中预约 | R | 右下大招入口；选招时也可点“大招” |
| 可选技能卡点 | 空格 | 共鸣 |
| 闪避 | J | 闪避 |
| 精准格挡 | K | 格挡 |
| 暂停 / 继续 | 主菜单或动作中 Esc；暂停时 Esc | 右上暂停 / 继续战斗 |

鼠标、键盘均可独立完成完整战斗，也可混用。Tab 保留原生按钮导航；菜单中的 Enter 确认当前选项，目标页 Enter 确认施放。子菜单和目标页的 Esc 先返回，主菜单 Esc 才暂停。

长按不重复产生输入，同一击仅接受第一次应对。过早输入失败，之后不能在同一击改选；不会锁住下一击。红光格挡无效，而且仍会消耗本击尝试，鼠标和 K 键一致。红光是招式限制提示，**不是立即按键的信号**。鼠标卡点／应对在按下时记录，不等待松开。

## 2.5D 空间与镜头

场景使用统一的三维坐标、透视投影和深度排序，配合多朝向二维毛怪与占位敌人。地砖、台阶、断柱、拱门、阴影和飘叶形成远近层次；镜头改变时有视差，近处立柱可以遮挡远处物体。平面地面与立体遮挡物分层绘制，避免地砖误挡角色底部。

| 阶段 | 镜头与交互 |
| --- | --- |
| 行动选择 | 毛怪位于左侧近景、敌人在远处，指令在角色身旁 |
| 技能 / 物品 | 镜头侧移、抬高，为技能名称与说明让出空间 |
| 目标预览 | 收起主菜单，推近敌人或回望自身，显示可点击目标框 |
| 玩家出招 | 侧面跟拍，毛怪跃向目标；卡点提示悬在动作附近 |
| 敌方行动 | 双方共同入镜，刀刃前摇、红光与逐击提示共享命中时刻 |
| 大招 | 使用较低机位与轻量上下遮幅，结束后恢复正常选招构图 |

镜头通常在 650ms 内平滑切换；正常卡点窗口到来前完成转场。QTE 按钮锚定该镜头下的固定世界位置，不跟着冲刺角色来回移动，便于鼠标操作。暂停同时冻结战斗与镜头。系统启用“减少动态效果”时镜头直接切换。窗口较窄时扩大视野，保留可见的操作区。

这是简化美术下的空间、镜头与操作参考；没有采用真实三维角色模型、骨骼动画或正式渲染管线。

## 时序与临时边界

- **速度调度：**每方初始排期为 `1000 / 速度`；完成正常行动后，在自己的排期上加同样的间隔。取较小排期执行，同速／同排期玩家优先。这是离散行动顺序，不是随现实时间增长的主动时间条。大招不修改排期。
- **完整行动：**开始时锁定选择、支付费用；之后播放前摇、逐击事件和 600ms 收束。收束结束才恢复正常菜单或插入已预约大招。一次敌人连击是一个行动。
- **反应窗口：**闪避为命中前 280ms 至命中瞬间；格挡为命中前 110ms 至命中瞬间；技能卡点为命中前 160ms 至命中瞬间，边界均包含。命中后输入不追溯改判。
- **重复输入：**当前击预备动作开始后，只接受第一次匹配的输入。后续连击的预备开始于上一击命中后 220ms，间隙不收输入，不提前替下一击决定。键盘自动连发不产生新尝试。
- **统一时钟：**规则使用毫秒时间戳，画面以同一时钟取进度。同一时间戳的输入先于该时刻伤害处理；更早的伤害仍先结算，不允许用晚输入倒退时间。单个正常帧可以按时间顺序处理多个事件。
- **暂停：**页面失焦／隐藏时冻结战斗；动作期间单帧停顿超过 250ms 也暂停，避免一次卡顿跳过多个反应机会。明确继续后恢复剩余时间。暂停期间不接收战斗输入或大招预约。
- **大招预约：**能量足够才可请求，仅保留一个预约；重复请求忽略。实际开始时扣除需求，选招期间先预览，确认请求后立即开始。大招不自我回能，也不能在大招执行中预约另一个大招。
- **死亡与胜负：**任意伤害使一方生命归零立即终止，取消剩余动作、判定及预约；同次结果双方为零时判败。已结算的伤害和奖励保留，未到行动末尾的普攻回资源／技能基础回能不再追加。当前招式没有双向同时伤害效果。
- **换装与重试：**仅战前搭配。胜负后可原搭配重试或回装配界面；资源和敌人循环全部重置。无存档、关间继承、关内换装或正式死亡回关规则。

## 实现与验证

`index.html` 中 `duel-core` 包含无 DOM 的战斗规则、`BattleMenu` 选择状态与投影数学；`duel-scene` 绘制透视场景、二维角色并插值镜头；`duel-ui` 连接实际按钮、键盘、HUD、暂停与结果页。测试直接提取并执行实际规则脚本，没有另外复制一套战斗实现。

在仓库根目录运行：

```powershell
node --test prototypes/hanser-duel/tests/combat.test.cjs
```

详见 [验证记录](VERIFICATION.md)。规则测试不替代玩家对读招、窗口和节奏的主观判断。

旧版 `prototypes/hanser-html/` 保留。本次不含格子走位、抽弃牌、提前备招、主动防御菜单、正式美术、客串角色技能、剧情、探索、Unity 工程或联网发布。本次透视场景与镜头只验证 HTML 参考表现，不能证明正式 Unity 镜头与资产管线已验证。
